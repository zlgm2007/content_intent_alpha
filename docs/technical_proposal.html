1. 问题分析

本项目的核心任务是：给定一个作品内容（如短视频/图文帖子）和用户评论，判断每条评论是否包含特定意图（如购物意向），并给出 0-5 分的意图强度评分。

关键挑战
  • 上下文依赖：评论的意图往往与作品内容相关，不能脱离内容单独判断。例如"多少钱"在购物视频下是购物意向，在搞笑视频下可能只是调侃。
  • 自定义意图：用户可以定义任意意图目标（购物意向、咨询意向、吐槽等），每个意图需要独立训练模型。
  • 评分而非二分类：需要 0-5 分的细粒度评分，而非简单的有/无。
  • 本地部署：模型需导出为 ONNX 格式，在本地 CPU 上高效推理。

3. 推荐方案：BERT 句对分类 + ONNX 部署

推荐方案

RoBERTa-wwm-ext 句对微调 → ONNX 导出 → INT8 量化 → ONNX Runtime 推理

选择此方案的理由：

  1. 句对输入解决上下文依赖：将作品内容和评论作为句子对输入 BERT，模型能理解评论在作品上下文中的含义。输入格式为 [CLS] 作品内容 [SEP] 评论内容 [SEP]，这是 BERT 原生支持的句对分类任务。
  2. RoBERTa-wwm-ext 中文表现最优：在全词掩码（Whole Word Masking）策略下预训练，在中文分类任务上稳定优于原版 BERT，是 CLUE 榜单上的常青树。
  3. ONNX 导出成熟：Hugging Face Optimum 提供一键导出，ONNX Runtime 在 CPU 上推理速度比 PyTorch 快 1.5-3 倍，INT8 量化后模型体积缩小 4 倍。
  4. 自定义意图灵活：每个意图目标独立训练一个模型，模型文件独立存储，互不干扰。切换意图只需加载对应的 ONNX 模型。

评分方案设计

0-5 分的评分可以通过以下两种方式实现：

方案 A：6 分类（推荐）
将 0-5 分直接作为 6 个类别，使用交叉熵损失训练。

优点：训练简单，直接输出分数
缺点：需要每类都有足够样本
适用：标注数据充足（每类 100+ 条）
方案 B：二分类 + 回归
先二分类（有/无意向），再对有意向的评论做回归打分。

优点：小数据集更稳定
缺点：需训练两个模型
适用：标注数据较少时

建议初期采用方案 A（6 分类），标注时直接打 0-5 分。如果某些分数段样本不足，可以合并为 3 类：无意图（0-2）、有意图（3-4）、强意图（5），后续数据充足后再细分。

5.5 ONNX Runtime 推理

import onnxruntime as ort import numpy as np from transformers import AutoTokenizer # 加载模型（单例，启动时加载一次） session = ort.InferenceSession("model_int8.onnx", providers=["CPUExecutionProvider"]) tokenizer = AutoTokenizer.from_pretrained("./onnx_model/") def predict_score(content: str, comment: str) -> dict: # 句对输入 inputs = tokenizer(content, comment, return_tensors="np", padding="max_length", max_length=256, truncation="longest_first") # ONNX 推理 logits = session.run(["logits"], dict(inputs))[0] probs = np.exp(logits) / np.exp(logits).sum(axis=1, keepdims=True) # softmax score = int(np.argmax(probs[0])) # 0-5 confidence = float(probs[0][score]) return {"score": score, "confidence": confidence, "has_intent": score >= 3}

5.6 分词说明（无需手动分词）

关键澄清

RoBERTa-wwm-ext 自带 tokenizer，直接传原始文本即可，不需要 jieba 分词。 "全词掩码"(wwm) 是预训练阶段的策略，不是推理阶段的分词方式。

处理流程：原始文本 → AutoTokenizer（模型自带，自动处理）→ token IDs → RoBERTa 模型 → logits → 评分。

只需一行代码：

# tokenizer 自动完成：加[CLS][SEP]、中文字符切分、英文子词切分、映射ID、生成mask、截断填充 inputs = tokenizer("这款口红太好看了", "求链接！想买！", max_length=256, truncation=True, padding="max_length")
步骤说明需要手动管吗
加 [CLS] [SEP]句首加 [CLS]，句间加 [SEP]不用
中文字符切分每个中文字 → 一个 token不用
英文/数字处理按子词切分，如 "2026" → "20"+"26"不用
映射到 ID查 vocab.txt，字 → 数字不用
生成 attention_mask标记真实 token vs padding不用
生成 token_type_ids标记作品 token vs 评论 token不用
截断/填充超 256 截断，不足补 [PAD]不用

6. 技术栈

Web 层架构：纯 Python stdlib 轻量 Server（参考 captcha_app）

不使用 Vue / FastAPI / 任何 web 框架。
后端：http.server.ThreadingHTTPServer + BaseHTTPRequestHandler，单端口，按 URL 前缀分发到各 API 模块。
前端：纯 HTML + CSS + Vanilla JS，iframe 标签页切换，无构建步骤。
零 web 依赖：requirements.txt 只需 ML 相关库（torch / transformers / onnxruntime），web 层全部用 Python 标准库。

层级技术选型理由
前端 纯 HTML + CSS + Vanilla JS 零构建、零依赖、iframe 标签页切换，参考 captcha_app
后端 Python stdlib http.server ThreadingHTTPServer 单端口分发，零框架依赖
ML 训练 PyTorch + Transformers Hugging Face 生态，模型加载/微调一站式
模型导出 Optimum + ONNX Runtime 一键导出、量化、跨平台推理
数据存储 SQLite (Python stdlib sqlite3) 零配置、本地文件、标准库自带
异步任务 threading.Thread (daemon) 训练任务后台线程执行，状态机管理

7. 数据库设计

数据规模

作品内容：上万条  |  评论数据：百万级累积  |  标注数据：百万级中标注子集
SQLite 完全可以承载百万级数据。关键优化：WAL 模式 + 索引 + 批量写入 + 分页查询。

7.1 SQLite 优化配置

# 连接时必须配置（百万级数据下性能差距巨大） conn = sqlite3.connect("intent_data/intent.db") conn.execute("PRAGMA journal_mode=WAL") # 读写不互斥 conn.execute("PRAGMA synchronous=NORMAL") # 安全且快 conn.execute("PRAGMA cache_size=-64000") # 64MB 缓存 conn.execute("PRAGMA temp_store=MEMORY") # 临时表走内存

7.2 表结构

-- 意图目标表 CREATE TABLE intent_goals ( id INTEGER PRIMARY KEY AUTOINCREMENT, name TEXT NOT NULL, -- "购物意向" description TEXT, created_at DATETIME DEFAULT CURRENT_TIMESTAMP ); -- 作品内容表（上万条） CREATE TABLE contents ( id INTEGER PRIMARY KEY AUTOINCREMENT, goal_id INTEGER REFERENCES intent_goals(id), text TEXT NOT NULL, -- 作品内容文本 created_at DATETIME DEFAULT CURRENT_TIMESTAMP ); CREATE INDEX idx_contents_goal ON contents(goal_id); -- 评论表（百万级，status 区分是否已标注） CREATE TABLE comments ( id INTEGER PRIMARY KEY AUTOINCREMENT, goal_id INTEGER REFERENCES intent_goals(id), content_id INTEGER REFERENCES contents(id), comment TEXT NOT NULL, -- 评论内容 score INTEGER, -- NULL=未标注, 0-5=已标注 label TEXT, -- NULL=未标注, has_intent / no_intent status TEXT DEFAULT 'pending', -- pending / labeled / skipped created_at DATETIME DEFAULT CURRENT_TIMESTAMP ); CREATE INDEX idx_comments_goal ON comments(goal_id); CREATE INDEX idx_comments_content ON comments(content_id); CREATE INDEX idx_comments_status ON comments(goal_id, status); CREATE INDEX idx_comments_score ON comments(goal_id, score); -- 模型记录表 CREATE TABLE models ( id INTEGER PRIMARY KEY AUTOINCREMENT, goal_id INTEGER REFERENCES intent_goals(id), onnx_path TEXT NOT NULL, -- 模型文件路径 tokenizer_path TEXT NOT NULL, accuracy REAL, -- 验证准确率 f1_score REAL, num_train_samples INTEGER, status TEXT DEFAULT 'trained', -- training / trained / failed created_at DATETIME DEFAULT CURRENT_TIMESTAMP ); -- 批跑结果表 CREATE TABLE batch_results ( id INTEGER PRIMARY KEY AUTOINCREMENT, model_id INTEGER REFERENCES models(id), comment_id INTEGER REFERENCES comments(id), predicted_score INTEGER, predicted_label TEXT, confidence REAL, is_correct BOOLEAN, created_at DATETIME DEFAULT CURRENT_TIMESTAMP ); CREATE INDEX idx_batch_model ON batch_results(model_id); -- 全文搜索（可选，百万级评论关键词搜索） CREATE VIRTUAL TABLE comments_fts USING fts5( comment, content='comments', content_rowid='id' );

8. 实施路线

1
工程搭建 + 意图目标管理
搭建 intent_app 轻量 server 骨架（ThreadingHTTPServer + common.py + 路由分发），实现意图目标的增删改查。SQLite 数据库初始化，index.html shell 页面 + intent.html 意图管理页。
2
数据标注模块
作品内容录入 + 评论标注界面。支持逐条标注（选 0-5 分），支持批量导入评论数据。标注数据存储到 SQLite。
3
模型训练引擎
集成 PyTorch + Transformers，实现 RoBERTa-wwm-ext 微调训练。trainer_engine.py 后台线程执行训练（状态机：idle/preparing/running/done/stopped/error），前端轮询 /train/api/status 显示训练进度。训练完成后自动导出 ONNX + INT8 量化。
4
批跑验证模块
batch_api.py 加载 ONNX 模型，对已标注数据批量推理（后台线程 + 轮询模式，与 captcha_app recognizer 一致）。输出识别率报告（准确率、F1、混淆矩阵），支持按分数段统计。
5
实时推理 + 优化
支持输入作品内容 + 评论，实时返回意图评分。模型切换、批量预测 API。前端 vanilla JS 交互打磨。
注意事项
  • 数据规模：作品上万条、评论百万级累积。SQLite + WAL + 索引完全可以承载，不需要 MySQL。百万级评论中标注子集用于训练。
  • 训练数据量：每个意图目标建议至少标注 500 条以上评论（正负各半），模型才能达到可用精度。数据不足时可先用方案 B（二分类）。
  • 分词：不需要手动分词。RoBERTa-wwm-ext 自带 tokenizer，直接传原始文本。"全词掩码"是预训练策略，推理时不涉及。
  • GPU 加速：训练阶段强烈建议使用 GPU（CUDA），CPU 训练 102M 参数模型约需数小时。推理阶段 CPU 即可（INT8 量化后约 15ms/条）。
  • 模型管理：每个意图目标可以训练多个版本的模型，保留历史版本便于回滚和对比。
  • 数据安全：标注数据中的评论可能包含敏感信息，建议在数据预处理时做脱敏处理。
